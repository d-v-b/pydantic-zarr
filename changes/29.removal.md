A field that a subclass adds to a node must now be a valid extra field of the node's metadata document. In `pydantic_zarr.v3`, it must be an object with `"must_understand": false`, or a field that the scope claims. So `label: str` is rejected, and so is `consolidated_metadata: dict | None = None`, because `null` is not valid consolidated metadata. In `pydantic_zarr.v2`, a group subclass cannot add a field, because a `.zgroup` document holds only `zarr_format`. To keep a field out of the document, declare it with `Field(exclude=True)`. `from_flat` and `from_flat_group` now raise `ValueError` for a node under an array, and for a key that ends with `/`. `from_flat_group` now validates its members as plain specs, so an array member is a plain `ArraySpec`, with the fields its class adds in `extra_fields`. Previously, any added field was accepted, and then lost or rejected when the hierarchy was written and read back. A node under an array was silently dropped.
