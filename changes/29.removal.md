A field that a subclass adds to a node must now be a valid extra field of the node's metadata document. In `pydantic_zarr.v3`, it must be an object with `"must_understand": false`, or a field that the scope claims, so `label: str` is rejected. In `pydantic_zarr.v2`, a group subclass cannot add a field, because a `.zgroup` document holds only `zarr_format`. To keep a field out of the document, declare it with `Field(exclude=True)`. Previously, any added field was accepted, and then lost or rejected when the hierarchy was written and read back.
